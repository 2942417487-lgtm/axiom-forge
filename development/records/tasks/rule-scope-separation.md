## 需求与已核对现状

用户要求将 AGENTS.md 作用域声明与研究 Runtime 指令加载分离纳入改动计划，避免把项目建设时对 Codex 的约束与系统运行时对研究岗位的约束混用。

现有 AGENTS.md 开头声明适用于所有 Agent、Runtime 与软件开发；其中同时包含证据主张分类、Canon／研究流程、软件任务说明、代码测试与 Git review 规则。axiom_forge/runtimes/core.py 当前把完整 AGENTS.md、agents/README.md 和岗位 Markdown 拼入研究指令。CodexRuntime 则以独立 software_engineer 接口拒绝研究／审计角色。

这是规则组织与上下文混放的证据，不证明任何真实模型已经误执行。研究输出的正式分类与字段仍有效；本计划不删除 FACT、INFERENCE、ENGINEERING ASSUMPTION、SPECULATION、CONFLICT、OPEN QUESTION 等业务枚举。

## 建议分层与适用对象

| 层 | 适用对象 | 保留的主要约束 |
| --- | --- | --- |
| 通用可信原则 | 开发 Agent、研究 Runtime、操作者宿主 | 不编造、来源与指令分离、授权范围、秘密保护、如实报告已实现／未验证状态 |
| 软件开发规则 | 当前开发对话、Codex 软件工程岗位、代码审查 | 任务说明、工作分支、适当测试、独立工程 review、人工 merge；开发文档区分现状／设计建议／待决策事项 |
| 世界观研究规则 | Researcher／Auditors／Lead／Red Team／Integrator | 固定 Canon Snapshot、首轮独立、交叉审查、科学证据与分类、计算回执、Canon 提案和独立人工审批 |
| 产品操作规范 | 导入／导出解析、用户审查与宿主数据操作 | 世界／项目／对话身份绑定、敏感输入处置、解析结果的来源映射、数据验证和用户选择；不自动继承软件开发交互习惯 |

共享行为不必重复实现，但必须声明各层的主体和条件。例如“独立工程设计审查”不等于四研究岗位首轮独立；“批准代码合并”不等于 CanonApproval；“用户接受导入映射”也不自动批准其包含的世界观主张。

## 后续改动顺序（需确认具体实施范围）

1. 逐条建立规则归属表，区分通用／开发／研究／宿主／产品操作。遇到兼属规则保留适用条件，不因拆分弱化禁止编造、密钥和 Canon 写入边界。
2. 审查规则文件布局。按已确认归属将开发入口与产品内部规则分开；通用原则、研究／宿主／产品操作规则的内部文件名与目录待设计审查，不从 world 数据加载任何执行规则。
3. 维护开发侧 AGENTS.md、CLAUDE.md：明确开发 Agent 的规则入口，保留必要项目现状、工程检查与资源信任说明；产品内部完整规则另行建立。研究分类不得被解释为每条软件沟通必须构造 ResearchResult／Evidence Ledger。
4. 调整研究 Runtime 指令组装：仅加载可信通用原则＋研究总则＋岗位／模式协议，不整份注入开发手册。明确导入原文件、模型解析内容和世界内 AGENTS.md 仍是数据。
5. 核对 CodexRuntime 和手工 Claude 岗位入口是否需要对应工程／研究入口声明；不扩大权限，不自动启动新岗位。
6. 更新可信资源定位、岗位登记、规则哈希和测试。因为恢复依赖资源／规则指纹，改动前定义在途任务的兼容方案；不能自动重签 checkpoint、替换固定指令或伪称旧任务仍可恢复。
7. 检查 research instructions 不含仅面向开发的测试／PR 指令，开发接口不被强制套入研究 Schema；同时验证各角色的权限和通用约束仍存在。
8. 独立审查具体差异，交付适当测试／契约／系统边界检查和恢复兼容结果，等待人工 review。

## 验收与本轮边界

- 研究角色的 FACT 等业务分类不变；开发沟通可用“已核对现状／设计建议／待决策事项”清楚区分判断性质，不让标签暗示正式世界 Evidence 已建立。
- 调用方身份、Runtime 职责、Canon 审批与软件开发 Git review 分开，不能通过新增文档绕过宿主权限。
- 新规则资源属于 EngineResources，世界包内同名文件不得成为可信政策。
- 完成分离后，产品研究指令与运行资源不加载外部开发侧 AGENTS.md、CLAUDE.md；移除开发资料仍可独立加载产品规则，产品发布范围排除开发入口。
- 在途任务／恢复哈希变化明确报告，不自动迁移或以厂商 Session 恢复。
- 本轮仅写此计划，并修订导入／导出草案的说明语言；不修改 AGENTS.md、岗位协议、Schema 或 Runtime 代码。

与 [导入／导出设计任务](world-portability-contract.md) 协同审查；规则拆分不作为启动 UI、语言全量转换或 Phase 12 的授权。
