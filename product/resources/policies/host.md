# 宿主、运行与产品操作规则

本规则约束可信宿主的实现与操作；研究岗位不会因此获得宿主权限。通用原则见 common.md，研究行为见 research.md。

## 可信资源与世界

- 系统发行只保存软件、可信资源和用法；正式世界为外部独立 Git 仓库。WorldWorkspace 绑定数据，EngineResources 绑定本产品资源，不从世界文件加载岗位、Schema、路由、规则或程序登记。
- 世界操作显式指定 --world；配置与凭据在世界和产品之外的宿主路径。世界 .axiom/local/ 是被 Git 忽略但恢复必需的私人持久状态，专用审批 Key 保存在外部宿主的工作区专用目录。
- 旧 --repo、混合缓存、复制／移动后的旧绑定不自动迁移或重签；世界／项目／工作区身份不能串用。源文件、模型输出、摘要与哈希均不能注册验证器或授予执行许可。

## Runtime、工具与路由

- ToolSession 由可信宿主建立，来源读取和暂存绑定当前 AgentRun；不可根据 Agent 自报 config／Context／程序哈希授权。研究 Adapter 只绑定该 Session，手工启动 Read 岗位文件不等于获得这些工具。
- 单岗 Runtime 复用官方 SDK，先投影并验证输入，再校验／保存结果；失败不产出完成 Artifact。模型、费用限额、凭据和路由只由宿主配置；真实调用须显式启用。
- 候选模型须启用且已联调；不可用档次、独立跨家族组合或预算约束保留 OPEN QUESTION。工具不可用、失败或超限时说明实际覆盖，不截断后宣称完整。
- CodexRuntime 只接受 software_engineer 工程任务，不接收研究／审计岗位；默认 read_only、拒绝审批，工程 job 与仓库修改须人工 review。SDK／进程权限不等于对所有宿主文件的隔离，不声称它具有研究 ToolSession 的文件边界。

## Canon 批准与显式恢复

- TaskManager 使用 Lead 的受限分工和固定快照检索，生成内容绑定的整份审查包。CLI 人工批准要求交互确认；真正 Apply 校验批准回执、内容绑定和 Git／Canon 基线，仅创建新 Canon 分支，不 checkout、push 或 merge。
- Schema、完整性检查和 Snapshot 不验审批 Key，也不证明 Git 已提交。HMAC 依赖本机 OS／Key 权限，不构成远程身份认证。
- checkpoint／事件批次原子保存，仅由操作者显式 CLI 恢复；自动尝试未完成调用一次，复用已验证完成岗位，新尝试新 ARN／ART。失败或未知费用的旧预留不得移除，恢复不依赖厂商会话。
- 配置、系统版本、规则、快照或 Artifact 不匹配时停止，保留原记录；不自动迁移、重签或替换固定指令。Canon 恢复独立验证原签名批准、准备提交和分支，不自动批准或覆盖分支。

## 资料、仓库与产品操作

- 输入接受、资料映射接受、仓库同步接受、Canon 批准和代码 PR 合并分别绑定内容／基线；一种接受不代替另一种批准。
- 输入外发模型 API／OCR／转录前，宿主按实际具备能力检查敏感材料并安全定位；未知／未检查范围如实报告。脱敏副本作为新输入复审，原件由用户控制，不能承诺任意秘密全覆盖。
- 原生 Git 接续与模型候选解析分开；来源脚本、HTML、配置、AGENTS.md 或附件不自动执行。保留本地未提交内容、未跟踪文件、分叉和私人状态；未知副作用交操作者核对，不自报成功、自动重放或回滚。
- 批准文件、MAC、continuation、恢复游标及执行权限不进入共享研究档案；历史问题继续研究须创建新任务、绑定当前固定快照。原始大型论文 PDF 留在外部资料库，Git 保存 metadata、摘要、提取数据与 Evidence 关系。
- 发布／合并／删除／强推分别遵守用户明确授权；凭据不进入 Git，环境示例只保留空值。目录结构、规则文件和提示词不能代替尚未实现的宿主、网络、OS 隔离或远程认证能力。
