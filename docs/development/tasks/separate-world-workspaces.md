# 系统与独立世界观工作区：基础分离改造

## 已确认的需求与本轮范围

用户已确认每个世界观从创建时建立独立本地 Git 仓库；系统源码与正式世界数据分离。本轮实现外部工作区创建/检查、可信系统资源与世界路径分离、任务/工具/Runtime/快照/审批/恢复绑定和离线验收。GitHub 连接、导出/重新导入、UI、语言翻译与 LangGraph 另行实施。

## 设计约束

- EngineResources 从系统安装资源或显式可信宿主路径读取 Schema、岗位、模式、路由和已审核程序登记；不从世界目录加载执行规则。
- WorldWorkspace 是独立 Git 根目录，不能位于系统资源/源码仓库内，也不能包含系统根目录；拒绝父 Git 仓库、symlink/junction 和错误世界身份。
- 保留 world/... 的逻辑数据路径和内容哈希；本机 durable state 位于世界工作区 .axiom/local/，被 Git 忽略但不是可随意清理的缓存。
- 凭据和专用审批密钥由显式外部可信宿主配置提供。代码改造不读取或迁移现有真实凭据/审批 Key。
- 所有研究对象绑定世界与工作区；模型无批准、正式 Canon 写入或 Git 写权限。Apply 仍只创建新 Canon 分支，不 checkout/push/merge。
- 规则/配置/系统版本和世界 Git 基线分别记录；拒绝不兼容的旧记录，不静默搬移/重签/恢复审批。
- 现有 world 空实例迁为模板/测试资料；保留历史 Git 提交，不重写历史。
- 初始化只在用户显式创建的空外部目标中写入有效空世界及独立 Git 基线，不覆盖既有文件。

## 验收

- 两个外部世界的文件、任务、Artifact、恢复、审批和 Git 不串用；同名世界内规则文件不影响可信指令。
- 系统目录不产生研究状态/正式世界数据；正常创建/研究/Canon Apply 不改变系统仓库。
- 新世界创建有效空数据、初始快照、Git 基线和忽略规则；错误路径、已有非空目录、父 Git 仓库被拒绝。
- 新路径回执保持业务身份/内容绑定，审批绑定目标工作区；旧布局明确拒绝并保留原记录。
- 现有独立研究、Evidence 回执、计算请求、预算预留、人工审批、一次恢复和分支保护继续通过回归测试。
- 检查 Schema/Contract/Routing、diff 格式、秘密与本机状态忽略规则；重要改动经独立审查。
