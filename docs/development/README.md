# 开发日志使用说明

本目录是系统开发的跨窗口接续入口。内容随项目 Git 版本共享；实际工作目录、分支和授权仍须现场核对。

## 接续顺序

1. 完整读取根目录 [AGENTS.md](../../AGENTS.md)，再读 [CURRENT.md](CURRENT.md)。
2. 核对 cwd、分支、HEAD、main／origin/main、暂存／未提交／未跟踪文件及 worktree；保留实际差异。
3. 读取 CURRENT 指向的当前接续任务，只执行用户授权范围；已完成任务的历史授权不自动延续。
4. 需要追溯时读取 [变更索引](CHANGELOG.md)、相关任务及 [历史记录](history/README.md)，不必每次重读全部历史。
5. 软件任务按 [工程技能说明](skills/README.md) 选择技能；产品用法从 [文档导航](../README.md) 进入。

旧交接书中的文档路径失效时，先查本目录 migration-map.json 的对应关系，读取迁移后的规范／任务，不重建旧目录或把旧状态当作现状。

## 记录规则

| 文件／目录 | 写什么 | 更新方式 |
| --- | --- | --- |
| CURRENT.md | 集成基线、功能状态、未完成项、当前任务与下一步 | 保留一份现状；事实附代码／任务／Git 来源 |
| CHANGELOG.md | 已集成变更与进行中的工作索引 | 每次集成追加一条，引用任务与提交／PR |
| tasks/ | 用户要求、范围、决定、实际执行／测试／审查和交付结果 | 一任务一文件；未执行的验收明确标注 |
| history/ | 原阶段交付、过去 README 中的开发说明 | 只作历史，保留日期、适用范围与来源；纠错追加说明 |
| skills/ | 本项目工程技能的用法、任务跟踪和文档约定 | 仅改工程流程，不授予发布或研究权限 |

结束一轮开发时更新当前任务和 CURRENT；功能用法改变才更新相应 README／指南。README 保留命令、接口、目录与必要限制，进度、测试次数、联调结果、PR 过程和机器排障记录集中到这里。

开发日志不是正式世界的 Evidence、Canon、批准或恢复记录。不要存入真实凭据、私人 .axiom/local、模型原始输出或个人资料；全局 Codex Memory 与被忽略的 .cache 不由本目录自动同步。旧缓存可保留用于追溯，不能代替已核对的现状。
